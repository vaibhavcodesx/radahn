# C8 implementation report

Implemented owner-scoped insights and graph plus a bounded hosted eval and local report CLI.

- Insights counts memory types/statuses, sums actual memory BSON document bytes via owner-scoped $bsonSize (not collection/index disk allocation), counts superseded old rows with supersedeReason=correction and updatedAt in the last seven days, and groups seven-day events by UTC date.
- Recall hit rate counts selected picks per recall trace in the last seven days; numerator counts distinct citedMemoryIds per assistant message in the same window. Repeated citation markup in a message counts once. Rate is clamped to [0,1], empty denominator is zero. Space-specific counts join currently existing owner/space memories; deleted memories cannot be attributed retrospectively to a space because traces/messages lack spaceKey.
- Graph emits the 1000 most recently updated units, explicit DTO node fields only, and supersede/evidence/related edges whose endpoints are both in the owner/space payload. Related links are canonicalized and deduplicated even for one-way references.
- 31 pure golden cases execute measured gate, semantic threshold, slot/history and expiry grace computations. Each case includes setupMemories/turns/expect metadata. This is NOT 31 end-to-end conversations. The checked-in results.md explicitly marks hosted metrics pending.
- Hosted runEvals() is restricted to database radahn and generates its own unique eval: owner. No externally supplied owner/database. Reads/mutations are exactly owner-scoped. finally attempts all memories/events/recalls/reflections/messages/conversations/spaces/settings/profile cleanup using allSettled; cleanup failures are exposed with cleanupSucceeded=false and the disposable owner id for recovery. Provider errors/content are never returned.
- Bounded live setup uses three write operation checks, one privacy write, three measured recall samples (immediate cold-index plan, exact, temporal), expiry exclusion, ambiguous-name forget refusal, explicit forget, and up to one generated memory/ghost pair. The ambiguity fixture spans current/global scope and verifies no deletion. No readiness wait hides the cold-index query. A/B uses the identical concrete served model, temperature 0, thinking settings and 180-token cap, with 15-second timeout per answer. Jaccard <0.7 is only a response-difference heuristic, not a quality judgment.
- Precision@5 uses fixed denominator five and recall@5 uses the expected active budget unit. Latencies use observed wall-clock samples. Counts/models and unmeasured nulls accompany metrics. Small samples intentionally avoid load on M0 and are not statistical performance claims.
- runEvals returns self-contained report data/Markdown without filesystem writes. npm run eval loads local env and calls POST https://radahn-ai.vercel.app/api/admin/eval (EVAL_BASE_URL override) with CRON_SECRET; no secret output, redirect following disabled. CLI writes evals/results.md locally. --deterministic performs no DB/network calls.

Review follow-up: the first implementation lacked a shared launch budget. A fake-clock regression observed a slow first write launching four writes, then passed after the guard (one write, budgetExceeded=true, zero recall samples, owner cleanup succeeds). Every new expensive phase must start in the first 60 seconds, leaving 210 seconds of work/cleanup headroom within the 300-second operator envelope. Fixture writes are individually guarded, avoiding multiple transaction retry windows in a single batch. Both generation calls check the shared deadline. There is no Promise.race leaving writes alive after cleanup. Provider attempts have existing 8/20-second timeouts and Mongo transactions have their existing retry bound. This is a conservative cooperative launch policy; a total Mongo network outage can still stall an underlying driver operation, so it is not a hard real-time cancellation guarantee. Global DB client changes were intentionally avoided; installed Mongo 7.8 timeoutMS APIs are deprecated no-ops. Cleanup failures are explicitly surfaced and include the exact disposable owner id for recovery.
